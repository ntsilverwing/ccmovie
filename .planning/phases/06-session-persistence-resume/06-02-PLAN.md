<objective>
Wire the engine-level resume path for FILE-03: an imperative
restoreSession(cues, persisted) on usePlaybackEngine that primes cues, plays,
then seeks to the offset-inclusive wall-clock position (fresh engines clobber
any pre-play seek), plus a guarded write-on-change persist effect that mirrors
session state into IndexedDB without ever deleting a record at boot.

Purpose: this is the correctness core of one-tap resume — Pitfall 2
(seek-before-play silently restarts at 0:00:00) and Pitfall 3
(delete-before-hydrate race) are both killed here.
Output: tested ordering contract in playbackEngine.test.ts; hook expose
restoreSession + persist effect.
</objective>

## Planner Assumptions (PA-n)

- **PA-4 (RESEARCH Open Question 4 — persist-effect placement + deletion policy):** resolved here. The persist effect lives INSIDE `usePlaybackEngine` (co-located with the session state it mirrors; App stays orchestration-only). Deletion policy deviates consciously from RESEARCH Pattern 2's write-only-on-non-null + explicit `stop()`/`onEnded` site-deletes: this plan uses the effect-driven form gated by `hasPersistedRef`, which kills the identical Pitfall-11 delete-before-hydrate race (mount fires no delete because the flag starts false) without cross-component ref wiring and without touching `stop()`/`onEnded` bodies. Both variants satisfy the safety property; this one is hook-local and StrictMode-idempotent. Risk if wrong: a boot-time record wipe — caught immediately by Task-2's behavior spec and by 06-03 device checkpoint step 2.
- **PA-1** (expiry threshold = 6h from `startedAt`, strictly-greater) is recorded in 06-01 Task 1; no re-litigation here.
