  <action>
Install `idb` (v8.0.3) as a production dependency. This is the only new runtime dependency for this plan.

Create `src/db/database.ts` with a typed DBSchema using `openDB` from idb. Define a `CinemaSyncDB` interface extending `DBSchema` with a single `subtitles` store:
- key: string (subtitle id — use a deterministic id derived from fileName + fileSize to avoid duplicates)
- value: `StoredSubtitle` type with fields: `id`, `fileName`, `cues` (Cue[]), `encoding`, `cueCount`, `importedAt` (number, epoch ms), `fileSize` (number)
- indexes: `by-fileName` (string), `by-importedAt` (number)

Export a `getDB()` function that memoizes the `openDB` promise (singleton pattern). The `upgrade` callback creates the `subtitles` store with `keyPath: 'id'` and both indexes.

Create `src/db/subtitles.ts` with the `StoredSubtitle` interface and four async CRUD functions:
- `saveSubtitle(sub: StoredSubtitle): Promise<void>` — uses `db.put('subtitles', sub)` (put = upsert, handles re-import of same file)
- `getSubtitle(id: string): Promise<StoredSubtitle | undefined>` — uses `db.get('subtitles', id)`
- `getAllSubtitles(): Promise<StoredSubtitle[]>` — uses `db.getAllFromIndex('subtitles', 'by-importedAt')` to return newest-first ordering
- `deleteSubtitle(id: string): Promise<void>` — uses `db.delete('subtitles', id)`

All functions must `await getDB()` internally. Wrap each in try/catch and throw a descriptive error on failure (e.g., `QuotaExceededError`).

Do NOT create a settings store in IndexedDB — settings remain in localStorage (Phase 2 decision: synchronous, sufficient for 2 key-values).
